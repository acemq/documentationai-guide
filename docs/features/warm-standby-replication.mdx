Warm Standby Replication (WSR) replicates schema definitions and messages from an upstream (primary) cluster to one or more downstream (standby) clusters. If the primary fails, an administrator promotes a standby into service as the new primary with minimal downtime or data loss.

<Callout kind="info">

Commercial-only — not available in open-source RabbitMQ. Included with your AceMQ license; see [What's Included](/start-here/whats-included).

</Callout>

## Two plug-ins, configured separately

WSR is implemented by **two independent plug-ins** that you configure separately. Both must be enabled and configured for full WSR.

| Plug-in | Replicates |
|---|---|
| **Continuous Schema Replication** (`rabbitmq_schema_definition_sync`) | Vhosts, queues, users, exchanges, bindings, policies, runtime parameters |
| **Standby Message Replication** (`rabbitmq_standby_replication`) | Messages published to quorum queues, classic queues, and streams |

<Callout kind="alert">

**AceMQ Insight**

The most common WSR setup mistake AceMQ sees is configuring schema replication and assuming messages are covered too. They're separate plug-ins with separate configuration. If you only did the `schema_definition_sync.*` settings, your definitions replicate but **your messages do not**.

</Callout>

## Terminology

| Term | Meaning |
|---|---|
| **Upstream (primary)** | The active source cluster |
| **Downstream (standby)** | The passive replica cluster |
| **Schema** | Definitions — users, vhosts, queues, exchanges, bindings, runtime parameters |
| **Sync operation** | A request/response pair: downstream requests, upstream returns the delta |
| **Downstream promotion** | Converting a standby into an independent primary during DR |

## Key design properties

- **Loose coupling.** Both sides are independent. If the link fails, the delta grows but neither cluster is otherwise affected. Downstreams syncing from a shared upstream don't coordinate with or interfere with each other.
- **Version independence.** A standby can run a different RabbitMQ version than the primary — all communication is asynchronous.
- **Per-vhost connections.** One connection per replicated virtual host, so load spreads across nodes. In a 3-node downstream with 10 vhosts, nodes own roughly 4/3/3 vhosts each for transfer and recovery.
- **Multiple standbys.** One primary can feed several standbys in different data centers.

## How message replication actually behaves

This differs by queue type and is important to understand before you rely on it:

- **Quorum and classic queues:** messages are written to an internal stream log on the downstream. They are **not visible in the Management UI and not in the destination queues until promotion.** At promotion, they're re-published to their original destination queues, filtered against the replicated acknowledgement log so already-processed messages are skipped.
- **Streams:** messages replicate directly into the destination streams on the downstream and **are** visible before promotion. You cannot publish new messages to them until promotion.

<Callout kind="alert">

**AceMQ Insight**

Because quorum/classic messages are invisible until promotion, "I don't see my messages on the standby" is expected behavior, not a fault. Verify with the diagnostic commands on [Diagnostics & Troubleshooting](/docs/features/warm-standby-troubleshooting) instead of looking at the Management UI queue counts.

</Callout>

## Prerequisites

- At least two RabbitMQ clusters — one upstream, one downstream
- **Stream protocol ports (typically TCP 6000–6500) open on the host firewall** and published on the container if running OCI
- If using TLS, the plug-ins need a **client** certificate generated with client-authentication use — and AceMQ recommends it be a different certificate from the broker's server certificate, so components have separate keys

## Enable both plug-ins

```bash
# Check status
rabbitmq-plugins list rabbitmq_schema_definition_sync
rabbitmq-plugins list rabbitmq_standby_replication

# Enable both at once
rabbitmqctl enable_warm_standby
```
