## Overview

Secure your Tanzu RabbitMQ cluster by managing users, virtual hosts (`vhosts`), permissions, and enabling TLS. AceMQ recommends least-privilege access and external auth providers for production. Use the RabbitMQ Management HTTP API at `https://rabbitmq.example.com:15671/api/` for automation.

<Callout kind="alert">
  Always use strong passwords and rotate credentials regularly. Enable TLS for all production traffic to protect against eavesdropping.
</Callout>

## Authentication Methods

Tanzu RabbitMQ supports multiple authentication backends. Switch between them based on your needs.

<Tabs>
  <Tab title="Internal Database" icon="database">
    Default method using RabbitMQ's built-in user database. Simple for small teams.
    
    <Steps>
      <Step title="Enable Internal Auth">
        Edit `rabbitmq.conf`:
      </Step>
      <Step title="Restart Cluster">
        ```bash
        kubectl rollout restart deployment rabbitmq-server -n rabbitmq-system
        ```
      </Step>
    </Steps>
  </Tab>
  
  <Tab title="LDAP" icon="users">
    Integrate with Active Directory or OpenLDAP for enterprise user management.
    
    ```toml
    auth_backends.0 = ldap
    auth_ldap.servers = ["ldap.example.com:389"]
    ```
  </Tab>
  
  <Tab title="OAuth 2.0" icon="shield">
    Use with Keycloak or Auth0 for token-based auth.
    
    Configure via plugin:
    ```bash
    rabbitmq-plugins enable rabbitmq_auth_backend_oauth2
    ```
  </Tab>
</Tabs>

## Managing Users and vhosts

Create users and assign them to `vhosts` via the Management API. Default `vhost` is `/`.

### Create a User

<ParamField path="users" param-type="POST" required="true">
  Endpoint to create users.
</ParamField>

<ParamField body="user" param-type="string" required="true">
  Username (e.g., `app-admin`).
</ParamField>

<ParamField body="password" param-type="string" required="true">
  Strong password (hashed in production).
</ParamField>

<CodeGroup tabs="cURL,Python,JavaScript">
  ```bash
  curl -u guest:guest \
    -H "content-type:application/json" \
    -X PUT \
    https://rabbitmq.example.com:15671/api/users/app-admin \
    -d '{"password":"securepass123","tags":"administrator"}'
  ```
  ```python
  import requests
  from requests.auth import HTTPBasicAuth

  auth = HTTPBasicAuth('guest', 'guest')
  data = {
      'password': 'securepass123',
      'tags': 'administrator'
  }
  response = requests.put(
      'https://rabbitmq.example.com:15671/api/users/app-admin',
      auth=auth,
      json=data
  )
  print(response.json())
  ```
  ```javascript
  const fetch = require('node-fetch');

  const response = await fetch(
    'https://rabbitmq.example.com:15671/api/users/app-admin',
    {
      method: 'PUT',
      headers: {
        'Authorization': 'Basic ' + Buffer.from('guest:guest').toString('base64'),
        'Content-Type': 'application/json'
      },
      body: JSON.stringify({
        password: 'securepass123',
        tags: 'administrator'
      })
    }
  );
  console.log(await response.json());
  ```
</CodeGroup>

<Response tabs="201,401">
  ```json
  {"user":"app-admin","tags":["administrator"]}
  ```
  ```json
  {"error":"unauthorized","reason":"Not management user"}
  ```
</Response>

### Create a vhost

```bash
curl -u guest:guest \
  -X PUT \
  https://rabbitmq.example.com:15671/api/vhosts/myapp
```

## Permissions and Access Control

Grant permissions per user per `vhost`. Patterns use regex: `.*` for full access.

| Permission | Configure | Read | Write |
|------------|-----------|------|-------|
| Management | `^$`     | `.*` | `.*` |
| Producer   | `.*`     | `.*` | `amq.*` |
| Consumer   | `.*`     | `amq.*` | `.*` |

Set via API:

```bash
curl -u guest:guest \
  -H "content-type:application/json" \
  -X POST \
  https://rabbitmq.example.com:15671/api/permissions/myapp/app-admin \
  -d '{"configure":"^$","write":".*","read":".*"}'
```

## TLS/SSL Configuration

Enable TLS for broker and management UI.

<Expandable title="Advanced TLS Setup" default-open="false">
  Generate certificates:
  
  ```bash
  openssl req -new -x509 -days 365 -nodes \
    -out rabbitmq.example.com.crt \
    -keyout rabbitmq.example.com.key \
    -subj "/CN=rabbitmq.example.com"
  ```
  
  Mount in Tanzu RabbitMQ:
  
  ```yaml
  tls:
    ca_certificate: /etc/rabbitmq/ca_certificate.pem
    clients:
      ssl_options:
        cacertfile: /etc/rabbitmq/ca_certificate.pem
        certfile: /etc/rabbitmq/cert.pem
        keyfile: /etc/rabbitmq/key.pem
        verify: verify_peer
        fail_if_no_peer_cert: true
  ```
</Expandable>

## Security Best Practices

- Disable guest user in production.
- Use separate `vhosts` for apps.
- Monitor logs for failed logins.
- Rotate TLS certs annually.

<Callout kind="tip">
  Audit permissions weekly using the Management UI at `https://rabbitmq.example.com:15672`.
</Callout>
