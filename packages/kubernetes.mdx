## What ships together

Tanzu RabbitMQ for Kubernetes installs as **one Helm chart, `tanzu-rabbitmq-operators`, which installs three operator images together:**

- `cluster-operator`
- `messaging-topology-operator`
- `default-user-credential-updater`

<Callout kind="warning">

Do not pin these operator images independently — install them as the bundle the Helm chart provides. Tanzu does not repackage the open-source Cluster/Topology operators; it ships its own certified set. If you're moving from a Bitnami/community Kubernetes deployment, this is a new deployment, not an in-place upgrade — see [Migrating Between Formats](/migrations/between-formats) and [From Open Source / Bitnami](/migrations/from-open-source).

</Callout>

## Create the pull secret

`acemq.jfrog.io` is a private registry, so Kubernetes needs an `imagePullSecret` before any pod can pull from it.

```bash
kubectl create secret docker-registry acemq-jfrog-pull \
  --namespace rabbitmq-system \
  --docker-server=acemq.jfrog.io \
  --docker-username=<jfrog-username> \
  --docker-password='<access-token>' \
  --docker-email=<your-email>
```

<Callout kind="warning">

**A pull secret is namespace-scoped.** Create it in *every* namespace that runs RabbitMQ workloads — a secret in `rabbitmq-system` does nothing for a pod in another namespace. A missing or wrong-namespace pull secret is the most common cause of `ErrImagePull` / `ImagePullBackOff`.

</Callout>

Reference it from a Pod, Deployment, or `RabbitmqCluster` resource:

```yaml
spec:
  imagePullSecrets:
    - name: acemq-jfrog-pull
  containers:
    - name: rabbitmq
      image: acemq.jfrog.io/rabbitmq-docker-remote/vmware-tanzu-rabbitmq:4.2.6
      imagePullPolicy: IfNotPresent
```

## Pull the chart

<Steps>
  <Step title="Authenticate" icon="key">

```bash
helm registry login acemq.jfrog.io \
  --username <your-jfrog-username> \
  --password <your-access-token>
```

Requires a recent enough Helm client to authenticate against Artifactory (Helm 3.8+).

  </Step>
  <Step title="Pull the chart" icon="download">

```bash
helm pull oci://acemq.jfrog.io/helm-remote/tanzu-rabbitmq-operators --version <version>
```

  </Step>
  <Step title="Install" icon="rocket">

```bash
helm install rabbitmq-operators \
  oci://acemq.jfrog.io/helm-remote/tanzu-rabbitmq-operators \
  --version <version> \
  --namespace rabbitmq-system --create-namespace
```

  </Step>
</Steps>

The operator images themselves live in `rabbitmq-operator-docker-remote` and are pulled automatically by the chart — you don't need to pull them separately.

## Deploying the broker

Once the operators are running, deploy a `RabbitmqCluster` custom resource pointing at the broker image (see [OCI / Containers](/packages/oci) for image path conventions). Declare durable topology — vhosts, queues, exchanges, policies — as Messaging Topology Operator custom resources under GitOps, not embedded in Helm values.

<Callout kind="info">

RKE2 is fully supported for Tanzu RabbitMQ, even though some Broadcom documentation lists only OpenShift and VKS.

</Callout>

## Helm values override

If you install via Helm and need to point the broker image at the AceMQ cache explicitly, override the image and pull-secret values:

```yaml
rabbitmqImage:
  registry: acemq.jfrog.io
  repository: rabbitmq-docker-remote/vmware-tanzu-rabbitmq
  tag: 4.2.6
  pullSecrets:
    - acemq-jfrog-pull
```

## Mirroring the full control plane

Tanzu RabbitMQ for Kubernetes ships supporting components alongside the broker — the cluster operator, messaging-topology operator, credential updater, audit-logger, and cert-manager. Each has its own image.

<Callout kind="alert">

**AceMQ Insight**

The `tanzu-rabbitmq-operators` chart pulls the operator images from AceMQ automatically. But if any part of your installation still resolves an image from upstream, that component won't be served from the AceMQ cache — which matters in air-gapped or egress-restricted environments where only `acemq.jfrog.io` is allowlisted. Contact AceMQ support to confirm what's in scope for your subscription before assuming the entire control plane is mirrored. See [Air-Gapped Environments](/packages/air-gapped).

</Callout>
